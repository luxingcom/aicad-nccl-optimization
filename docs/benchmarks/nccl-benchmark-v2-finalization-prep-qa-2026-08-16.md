## 2. 独立复核协议（FIX 数据到位后按序执行）

### 2.1 DQ（数据质量）门禁
- [ ] 完整性：4 档齐全；rows 数 = 54；monitor 采样覆盖 4 档；manifest/precheck/bench_cfg 齐全。
- [ ] 参数一致性：bench_cfg 与 v0.1 对应档**同参**（mode=pr、prefix_len、concurrency、rounds=3、cooldown 30、monitor 2s、request-timeout 1800 或 ≥600 读超时）；仅超时/分类修复。
- [ ] 引擎状态：precheck running=0；四机 healthy；同一生产实例无重启；dspark 起始值无异常漂移（与 v0.1 precheck 数量级一致）。
- [ ] 无污染：FIX 窗口与生产操作无重叠（时序交叉）。

### 2.2 purity 复核
- [ ] 每档 `reached_full_concurrency=True`；`overshot=False`（**重点：PR_C4_L131076 v0.1 曾 overshoot=True 须消失**）。
- [ ] monitor 峰值 == 预期 C（C2→2、C4→4、C6→6）；`n_during_at_c` 高；`monitor_read_errors=0`。
- [ ] short 档判定不适用（131K/32K 均长档，应有充分采样）。

### 2.3 acceptance 复核
- [ ] 4 档 `acceptance=1.0`（修复后 60s 读超时不再触发）。
- [ ] `err_samples` 空；status 无 `timeout`/`other`/`conn_err`/`http_err`/`model_err`。
- [ ] 修复分类生效：若仍有失败，须为真实引擎失败（finish_reason=error / 引擎超时），QA 逐条核 err 原文。

### 2.4 与 v0.1 一致性（同参直比）
- [ ] **PR_C6_L32768 与 v0.1 部分成功 12 条直比**：v0.1 成功 12 条 per-req TTFT 40.3-44.2s、prefill 652-713 tps → FIX 全量 18 条 p50 TTFT 应在同量级（预期 ~40-47s）、p50 prefill ~650-720；wall-agg 应显著高于 v0.1 被稀释值 1910.2（预期 ~2500-2700）。
- [ ] 131K 三档（C2/C4/C6）与 C1_L131076（v0.1 有效）单调性核对（见 2.5）。

### 2.5 物理一致性（单调性软界，非硬门）
- **131K 串**（v0.1 C1 已知：TTFT p50=53.691s、prefill p50=2147.0、wall-agg=2142.6）：
  - TTFT：C1 < C2 < C4 < C6（并发争用单调升）；预期 C2~70-110s、C4~100-200s、C6~150-300s（§6.4 注）。
  - per-request prefill p50：C1 > C2 > C4 > C6（单调降）。
  - wall-agg：C1 2142.6 → C≥2 应 ≥ C1 或略升（prefill 批共享，参考 L32768 串 C1→C4 2381→2759 的 +16% 趋势）。
- **L32768@C6**：与 L32768@C4（v0.1：TTFT 41.517、prefill 694.2、wall-agg 2759.4）比：C6 per-req ≤ C4、wall-agg ≈ C4 或略低。
- 软界命中说明：预测量为统计期望带，**不构成否决**；偏离 >2σ 则 QA 标注并查因（先查是否引擎侧长前缀调度排队，再查工具）。

### 2.6 v1 锚定对照（重述，FIX 不改变锚定结论）
