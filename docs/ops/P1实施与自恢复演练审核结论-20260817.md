## 四、关键发现（已实锤）

1. **覆盖缺口实锤**：容器存活但 API 挂（EngineCore 故障）原本无自动恢复——docker HEALTHCHECK（只查进程存活）与 systemd monitor（docker wait 阻塞）均无感知。修正版 healthcheck-rebuild.sh（探针直查 8001 /health → docker rm -f）验证成功，**精准补缺口**（5min12s 恢复）。
2. **PID namespace 保护**：容器内 `kill -9 1` 无效（pid1 免疫同 namespace SIGKILL），进程级故障只能 kill 子进程（EngineCore）→ 该场景必须依赖外部探针（healthcheck）检测。
3. **FORMGE≥3 TCP 残余连接竞态（保守设计）**：守卫用 TCPStore 连接数启发式，快速重启时可能多余全链重建（成本 ~5min），但方向保守（宁重建不留半集群），正确性有保障 → P2 细化。

## 六、healthcheck-rebuild 启用方案（推荐：systemd timer，仅 head 01）

```ini
# /etc/systemd/system/vllm-healthcheck.service
[Unit]
Description=vLLM TP4 API healthcheck & auto-rebuild
After=docker.service

[Service]
Type=oneshot
User=<svc-user>
ExecStart=/opt/aicad-prod/scripts/healthcheck-rebuild.sh --role head --cooldown 1800

# /etc/systemd/system/vllm-healthcheck.timer
[Timer]
OnUnitActiveSec=60s
AccuracySec=5s
Persistent=true

[Install]
WantedBy=timers.target
```

**选 timer 理由**：原生可靠无外部依赖、Persistent 补跑、日志入 journal、与现有 unit 体系一致；`--cooldown 1800` 与模型加载匹配防重建中二次触发。

**外部告警链路（grafana）仅作 P2 增强，不替代自动恢复**——自恢复目标由 timer 兑现。

**部署要点**：部署前 bash -n + .bak；`systemctl enable --now vllm-healthcheck.timer`；启用后 `journalctl -u vllm-healthcheck` 观察一窗口（探针正常时应 exit 0 不触发重建）。
