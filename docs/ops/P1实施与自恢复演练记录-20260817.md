## 5. 关键发现

### 5.1 🔴 覆盖缺口：容器存活但 API/EngineCore 挂（生产自愈链盲区）

- 现象：EngineCore kill → vLLM API shutdown（8001 挂），但容器主进程 pid 1 卡在关闭流程未退出 → **容器不退出**。
- 影响：
  - systemd monitor 的 `docker wait` **永久阻塞**，不触发重建；
  - docker HEALTHCHECK 仍显示 **healthy**（只查进程存活，不查 API 可达）；
  - → 当前生产自愈链**只覆盖"容器退出"场景**，不覆盖"容器存活但 API 挂"场景，会无限期停服。
- **对策（P1 已部署）**：`healthcheck-rebuild.sh` 探针直查 `8001 /health`（API 级），失败即 `docker rm -f` 触发重建——正好补上该缺口。**但尚未启用，缺口仍裸露**（见行动项）。

### 5.2 PID namespace init 保护

- 容器 pid 1（vLLM 主进程）免疫同 namespace 的 `kill -9`，只能被宿主机 `docker kill` / `docker stop` 终止。运维注入故障时须用 `docker kill` 或 kill 非 pid1 子进程（如 EngineCore）。

### 5.3 互杀守卫 FORMEd 判定的竞态

- 演练 1 中互杀守卫触发（FORMED≥3），但该计数含 TCP 残余连接：rank1 被杀后瞬间 head 侧仍可能计数 ≥3。当前设计为保守策略（任一 rank 缺失即全链重建），可接受，但需知悉存在瞬时误判可能。

### 5.4 启动脚本硬编码 log-opt 覆盖 daemon 默认

- `start_tp4_head.sh` / `start_tp4_worker.sh` 硬编码 `--log-opt max-file=3` 会覆盖 daemon.json 全局 `max-file=5`。本次已同步修正为 5（P1 第 4 项完整生效）。后续新增容器/镜像刷新需保持此一致。
