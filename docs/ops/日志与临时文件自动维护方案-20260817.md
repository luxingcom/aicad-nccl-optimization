- 日期: 2026-08-17
- 作者: SRE 工程师 Rex
- 范围: DGX Spark 四机 (<node1>-04) 生产环境 vLLM TP4 (deepseek-v4-flash-0731, 库 2be94172)
- 状态: 已部署并验证

## 1. 现状核验结论

| 项目 | 实测结果 | 说明 |
|------|---------|------|
| /var/log/vllm/ | 四机均不存在该目录 | vLLM/nccl 日志实际落在 docker 容器 json.log 与 /tmp |
| vllm-tp4 容器日志 | rank0@01=2.8M, rank1@02=39K | 已带 docker 级轮转 `--log-opt max-size=100m,max-file=3` |
| 其他容器日志 (aicad-*/dcgm/node-exporter) | grafana 8M 最大, 其余 <200K | **无任何轮转** (json-file 默认), 长期运行会无界增长 |

## 2. 已部署措施 (即时生效, 无需重启 docker)

### 2.1 logrotate 兜底配置 `/etc/logrotate.d/vllm-tp4` (四机)
- 目标: `/var/lib/docker/containers/*/*-json.log` — 覆盖**未配 docker 级轮转**的容器 (aicad-* 等)
  - `size 100M`, `daily`, `rotate 5`, `copytruncate`, `compress`, `delaycompress`
- 目标: `/var/log/vllm/*.log` — vLLM/nccl 落盘日志统一目录 (已创建, 防长期膨胀)
  - `daily`, `rotate 14`, `copytruncate`, `compress`
- **关键**: 必须 `copytruncate` — 容器进程持有日志 fd, rename 会导致后续写入丢失
- 说明: vllm-tp4-rank* 已由 docker 自身轮转 (100M x 3), 本配置仅在文件超 100M 时兜底, 双机制并存无冲突

### 2.2 journald 上限 (四机)
- 新增 drop-in `/etc/systemd/journald.conf.d/zz-sre-limit.conf`: `SystemMaxUse=500M`
- 已 `systemctl restart systemd-journald` (不影响生产容器)
- 效果: journald 占用从 1.0G/684M 降至 494M/465M/488M/494M

### 2.3 每周自动维护 crontab (root, 四机)
```
30 3 * * 0 /opt/aicad-prod/scripts/maintenance/clean_tmp_logs.sh >/dev/null 2>&1
```
脚本内容 (clean_tmp_logs.sh):
1. `/tmp` 普通文件 >30 天删除
2. `/tmp` 已知测试残留目录 (v027*/v026*/nccl-*/fi015*/fi016*) >30 天删除
   (绝不删 systemd-private/snap-private/nvidia)
3. `/opt/aicad-prod/verification-logs/` >30 天文件删除 + 空目录清理
4. `docker image prune -f` (仅 untagged dangling 镜像)
运行日志: `/var/log/vllm/maintenance.log`

## 3. 验证证据
- logrotate 干跑: `logrotate -d /etc/logrotate.d/vllm-tp4` → 四机 exit 0
- logrotate 真实触发: 临时测试配置验证 copytruncate + gzip 生效 (app.log → app.log.1.gz)
- crontab: `crontab -l` 四机确认条目
- 维护脚本手动运行: 四机 exit 0, maintenance.log 有记录

## 4. 遗留建议 (需 team-lead 批准, 下次维护窗口执行)
**daemon.json 增加全局容器日志轮转** — 需重启 docker, 影响生产容器, 本次未执行:
```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "5"
  }
}
```
- 影响: 新创建容器生效; 现有容器需重建 (vllm-tp4 已自带, 主要受益 aicad-* 等服务)
- 建议: 下次有计划重启/重建窗口时, 由 team-lead 审批后执行

## 5. 回滚方式
- logrotate: `rm /etc/logrotate.d/vllm-tp4`
- journald: `rm /etc/systemd/journald.conf.d/zz-sre-limit.conf && systemctl restart systemd-journald`
- crontab: `crontab -r` (或编辑移除条目)
- 脚本: `rm /opt/aicad-prod/scripts/maintenance/clean_tmp_logs.sh`
