## 3. 结构信号判读（对照口径 §3.1-§3.3）

## 5. 测量异常标注（QA 独立发现，需根因）

**现象**：2hop 的 aligned/nobar 关系**反转**，仅 2hop 出现：

| 项 @1K auto | aligned (µs) | nobar (µs) | mean/p50 |
|---|---|---|---|
| ring_manual | 717.9 | 312.9 | 正常（aligned>nobar，barrier 开销） |
| **2hop** | 471.4 | **867.7** | **反转 + 重尾（mean/p50=1.94x）** |

- ring_manual nobar mean/p50 = 313/300（1.04x，稳定）；2hop nobar mean/p50 = 868/448（1.94x，重尾）；2hop aligned mean/p50 = 471/436（1.08x，稳定）。
- 解释：2hop 双边步（rs1_bilateral/ag1_bilateral 同时双口 send+recv）在**无 barrier 的 pipelined 执行**下，与后续 forward 步争用同一 HCA 端口 → 偶发背压/阻塞 stall → 重尾总时。ring_manual 单口顺序步无此争用。
- **影响**：主判据 ratio_m_nb 的分母/分子（2hop_nobar）被该伪影污染 → 呈现"2hop 更慢"。
- **与 V2b 一致性**：V2b δ_hw 256K=1.81 / 368K=3.10（≥1.7 档）直接印证**双边端口争用是真实硬件现象**，非仅 torch 代理伪影——即真实 kernel 若不解决 per-port 调度（口径 P2 前置），同样会吃这个损失。

### 7.2 分歧解释（为何简报乐观、QA 判 NO-GO 信号）

- 简报引用的是 **ratio_m（aligned）**——口径文档 X4 已明确"废用；一律用 nobar 版本"；且该"利好"仅 auto 协议 1-64K，ll/simple 不支持。
- 口径的**主判据是 ratio_m_nb（nobar）**——实测全协议小尺寸 >1，结构收益未现。
- 一句话：**按已 Accepted 的口径，S2 数据给出的是结构性 NO-GO 信号，而非 GO。**

### 7.3 QA 建议（避免终审误判）

1. **先做定向诊断（1-2 天）再终审**：针对 2hop nobar 重尾/反转异常，验证是否 torch-P2P 代理的双边端口争用伪影：① 重跑 2hop nobar 增加 per-step 轻量 sync 或交错端口分配；② 对照 V2b 的 t_right/t_left/t_both 原始分布确认争用源；③ 若伪影确认 → ratio_m_nb 判据作废该档，回到 aligned ratio_m（auto 0.66-0.74）+ δ_fwd（auto 0.82-0.96）的结构证据，可转 **GO 降级（S3 小步原型）**；④ 若争用为真实算法特性 → 维持 **NO-GO**。
2. **立即确认 V3 Test B 失败档位**：B≥8 失败 = N2 硬否决，无需诊断直接 NO-GO；仅 B=1 失败则降为信息项。
3. **补数据**：请 Rex 回传 v2b.json、v3.json、bench-rank0-*.log（本地现只有 V1 JSON），QA 独立复核 δ_hw 与 V3 判定 + DQ4/时序最终确认。

5. **口径修订建议（供 Archi）**：若定向诊断确认 nobar 伪影，建议口径将 S1 主判据在"2hop 双边步存在端口争用"场景下改为 aligned ratio_m + δ_fwd 组合，或明确 nobar 仅在无争用区（单口路径）可用。

## 11. P5 判读框架 QA 复核意见（2026-08-16，S3 门规格 §3）

> 架构师门规格 `nccl-2hop-s3-phase1-gate-spec-architect-2026-08-16.md` 请 QA 复核 P5（G3 收益主闸）。以下为 QA 意见（已直接回传 Archi；与规格无冲突，均为加固项）。

### 11.1 阈值 0.80 / 0.88 —— 认可，附稳定性防线

- **0.80 合理**：理论 4/6≈0.667；S2 aligned ratio_m（auto）1K-64K=0.66-0.74、δ_fwd=0.82-0.96 → 真实 kernel（无 torch 每-op 开销）若步数收益为真应落在 0.67-0.75，0.80 留 ~7-20% 余量，可达成且非放水。
- **0.88 合理**：= 原 S2 N1' 结构失败线；>0.88 即收益 <12%，配 8-12 人日不值 → NO-GO 成立。
- **⚠️ 需加重复性防线（最重要）**：单次 iters≥200 的 p50 是点估计，S2 已多次证明单轮/单尺寸可被重尾与噪声带偏。**G3 判定要求 @16K 至少 2-3 轮独立 A/B**，取 ratio_real(p50) 的中位数，且各轮须落在同一侧（或 ≥2/3 同侧）；**若落在 0.78-0.82 边界带 → 强制加跑一轮**。禁止单轮定 G3。

### 11.2 多尺寸组合（补强，防单尺寸误判）

- 主判据 16K ≤0.80 之外，建议 **G3 通过附加"1K 参考不失败"**：1K 是步数收益最有利档，若 16K 过但 1K >0.88（或反超），说明存在尺寸相关异常 → 先查原因再放行。
- 4K/64K 描形**建议改为必测**（成本极低，小尺寸 iters 快）：确认 ≤64K 路由带内 ratio_real 全线 ≤0.88，否则"降级 ≤16K 路由"的前提（仅 16K 好）不成立。

### 11.3 p99 纳入 —— 信息项 + 升级规则，非硬闸

- 认可 p99 作 decode 尾部参考（kernel 步同步，尾部相关），但 **p99 单点噪声大，不宜作硬闸**（与 V3 Test C 尖峰=告警非否决同逻辑）。
- 建议规则：报告 2hop/ring 各自的 p50/p95/p99 + `ratio_real(p99)`；**ratio_real(p99) > 1.2 → P6 e2e decode 尾部验证升为必做**；> 1.5 → P2 per-edge 调度复查。不做 G3 否决项，作 full 阶段看护项。

### 11.4 δ_hw@16K 联动（明确边界行为）

- 规格已并入 δ_hw@16K（p50 判据），但**需明确与 G3 的联动**：
  - δ_hw(p50)@16K **≥1.7** → 在 G3 判定尺寸上双边争用串行化 → **G3 自动降级/重评**（收益前提动摇）；
  - 1.3-1.7 → G3 仍按 ratio_real 判，但 **P2 per-edge channel 调度成为 full 放行的显式前置**；
  - ≤1.3 → 理想，正常推进。

### 11.5 数据/报告标准（QA 独立复算基础）

- 每尺寸报：N、avg、p50、p95、p99、ok、block_timeouts；**同时给 ring 与 2hop 的原始分布**（不只 ratio），QA 独立复算 ratio_real 并核对重尾（avg/p50>1.5 → p50 为准并标注）。
- **连接 priming 确认**（防 S2 首块 lazy-connect 污染）+ 每尺寸 warmup 计数 + DQ（lib md5、NCCL_ALGO、env）+ 生产隔离 pre/post 记录。
- ring 基线须与 2hop **同容器/同 env/同 lib，仅 NCCL_ALGO 不同**（规格已明确，QA 复核时核对）。

### 11.6 基线衔接确认

- 规格引用 BenchV2 基线（32K PR 2425 / 131K PR 2200 / DE 全档）与 QA 报告一致；G3 通过后 P6 e2e 对回该基线，QA 将同步复核 e2e 判读。

**QA 结论**：P5 框架**可执行**；以上为加固项（重复性防线、多尺寸组合、p99 升级规则、δ_hw 联动），不改变门结构。建议在开窗前将 11.1-11.4 落入规格 §3。
