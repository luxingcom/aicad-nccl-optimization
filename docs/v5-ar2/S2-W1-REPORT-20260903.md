## 一、四机 GPU 实测（M1 eager inline，200 iter，bf16 精确校验独立 pass）

| 尺寸 | ar2 M1 p50 (µs) | NCCL ring 基线* (µs) | 判定 |
|---:|---:|---:|---|
| 1KB | **20.5** | 28.3 / 34.5 | **-28% / -41%** |
| 4KB | **24.9** | 31.4 / 37.6 | **-21% / -34%** |
| 16KB | 43.3 | 38.8 / 46.6 | avg -11% 落后 / p50 -7% 领先（持平带） |
| 32KB | 66.7 | — | 交叉区 |
| 64KB | 112.3 | 69.9 | 落后（价值区外，维持 ring 判定） |

\* 基线=窗口 2 同环境 torch NCCL AR（avg/p50）。四 rank 计时高度一致（±0.1µs）。

**价值区定版：≤8KB 显著收益，16KB 持平，≥32KB 交还 ring。** `ar2_recommended()` 交叉点默认 32768 待 M2 落地后按 layer 口径重定。

对照窗口 2 SparkRing 原生探针（4KB 21.2µs）：本模块 M1 24.9µs 慢 3.7µs——代价换来的是完整错误模型（返回码/abort 传播/poison）+ C API + 图模式预留；1KB 段 20.5µs 为全项目最快记录。

## 二、错误模型验证（对标 SparkRing 四处强化的实证）

1. **单机自测全绿**：正确性 4K/64K×100 ✓；超时 300ms→TIMEOUT 精确返回 ✓；**ABORT 门铃传播：对端 33µs 快速失败**（SparkRing 语义是各自等满 5s deadline）✓；10k op RSS Δ=4KB（数据路径零分配）✓；API 契约（毒化/UNSUPPORTED/幂等 finalize）✓。
2. **G3 死亡测试（真实集群）**：rank1 第 30 op `_exit(9)` → 存活 3 rank **6 秒内全部干净返回错误码**（rank3 5s deadline 先触发 → ABORT 门铃+TCP 中继级联释放 rank0/rank2，均 rc=-4 aborted）；无挂起、无进程 abort、容器可干净重启。优于参考实现（SparkRing fatal=进程 abort + kernel 无限 nanosleep 占 SM）。
3. 内核 abort 感知退出实装（wait_two 检查 abort 槽，出错写 dev_err 编码后正常返回）。

## 三、M2 layer-graph 模式：1 个未解 bug（证据链完整）

现象：8-op 整层 capture 后 replay，~136 个 replay（约 op 1088/1160 处）内核报 PROTOCOL。诊断编码（kernel 观测值带回）：
- 第一次：want-seq=1088, linkB
- 第二次：**want-seq=23, obs-db=1160** —— 某个 graph 内核带着 replay 3 的旧 seq 字在 ~145 个 replay 后才执行/或观测到远超前的门铃

推演过的竞态链（槽复用/bell 超前/stream 序）全部闭合，唯一未闭合解释：**graph 内核读取 seq_word 与 host 跨 replay 重写之间的可见性/调度时序**。修复方向：① seq 字改为 per-replay 递增的 device 端计数器（kernel 不读 host 字，改从 ring claim，SparkRing graph_publish_command 模式）；② 或 replay 前对 seq_words 做 device 侧 fence。**M2 冻结待修，不影响 M1 结论。**

## 四、本轮修复的 bug 清单（全部有实锤根因）

1. rank 字节 recv 写 1B 到 `int r=-1` 高位保留 0xFF → 负数被拒（proto v2 注释明示，照抄时改错了初值）
2. 同一 socket 重试 connect——ECONNREFUSED 后 fd 即废，240 次重试全是假失败（proto 未踩中是时序运气：其 rank0 先 listen）
3. 探针 `--peers` 解析后 free，cfg.peer_ips 悬挂指针 → inet_addr 读垃圾 → 秒败超时
4. engine_wait 的门铃超前判定跨轮误报：done(n) 等待期间对端 dbellA 合法可到 n+1（轮内严格性归 kernel wait_two）
5. CPU 后端槽步长用 op 字节而非 smax（与 post 路径不一致）
6. 门铃字为 0（未到达）被当 magic 错误立即报 PROTOCOL（应视为未到达继续自旋）
7. op 入口无 abort 预检 → 对端已 abort 后仍向死 QP post，吃满 transport retry（3.5s）

另：docker exec 不传播 timeout 信号 → 僵尸探针占端口，runbook 增加"容器内 pkill 后再跑"步骤。
