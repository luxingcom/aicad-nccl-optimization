## 一、M2 根因调查链（本窗口 9 轮）

| 轮 | 实验/改动 | 结果 | 结论 |
|---|---|---|---|
| 1 | m1 单缓冲 1020 op | 全绿 20.8µs | 排除 op 数阈值，坐实多缓冲相关性 |
| 2 | 有界偏斜容忍 (d==seq+1) + skew 计数 | 未愈（当时） | 真协议缺陷已修但症状另有来源 |
| 3 | 周期校验 ==10.0f | 全线 WRONG | **校验器期望值 bug**（时序循环值 ×4/调用） |
| 4 | 期望改几何级数 10×4^k | 仍 WRONG（1.27e31 vs inf） | "冻结在 4^50"——误导主线 3 轮 |
| 5 | 整数指纹 buf i=(r+1)+2^(i-2)→base=10+2^i | rank0 收到无指纹旧值 | **分发事故**：远端跑旧二进制——rsync+md5 纪律补上 |
| 6 | 引擎快照环 (sA/sB/rA/rB 每 op) | sA=一代旧值 | 排除传输丢失：NIC 交付=engine 所读 |
| 7 | __stwt/__ldcv 缓存序内在函数 | 症状逐字节不变 | 排除 L2 可见性假设 → 非竞态、确定性 |
| 8 | kernel 金丝雀 (读到的 x/写出的 sA) | kernel 读到的就是"旧值" | kernel 视角滞后一代、memcpy 视角新鲜 |
| 9 | NO_GRAPH 二分 | 同样失败 | 排除 CUDA graph 语义 → 指向 probe 自身 |

**定谳**：probe 首次 verify 后的 H2D refill（默认流）与 ar2 流尾 kernel 最终写**异步竞态**——refill 赢则整代增长被重置，
表象="冻结/滞后一代"；配合期望公式错位放大成"数据损坏"。协议、引擎、NIC、CUDA stream 语义全部无辜。
教训两条：①跨机二进制必须 rsync+md5 内容级核对（与镜像同 tag 异 ID 同一陷阱）；②校验器本身是代码，
期望值错误与被测物错误不可区分——需要可区分的指纹设计。

**保留的真修复**（相对 SparkRing 参考的强化）：
- kernel `wait_two` / CPU `wait_dbell`：d==seq+1 合法早到（槽数学保证 seq 数据完好），d>seq+1 才 PROTOCOL；
  skew 计数（word1）finalize 打印——本轮全部回归 skew=0（容忍从未触发，但堵住理论窗口）
- `__stwt`/`__ldcv`：槽访问缓存序内在函数（write-through 直达系统内存 / 绕 L2 读）——防御性保留
- AR2_DUMP 取证：engine_seq/claim_ctr/双 ctl/32-op 快照环（时间线+槽首 8B）——生产可随时启用
